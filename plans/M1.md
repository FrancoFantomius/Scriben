# M1 — Canonical Document Model + Storage Migration

**Goal:** Introduce a block-based JSON document model that becomes the single source
of truth for document content, decoupled from pagination. No user-visible behavior
changes. Establishes the pivot used by every import/export milestone.

## Context / why

- Scriben stores documents as an array of per-page `innerHTML` strings in PouchDB
  (`js/editor/document.js:50`, `saveContent()`), edited with `document.execCommand`
  (`js/editor/commands.js:75`), and paginated at render time (`js/editor/pagination.js`).
- `document.execCommand` produces arbitrary DOM (inline `<span>`/`<font>` nesting,
  `data-split` nodes from pagination, `.page-break` divs), which is not a stable
  representation for DOCX conversion.
- The model is the contract both `docxExport` and `docxImport` compile against.

## Tasks

### 1. Define the model schema — `js/editor/model.js`
- Block node types: `paragraph`, `heading`, `listItem`, `image`, `link` (block link),
  `table`, `pageBreak`, `horizontalRule`, `section` (page format / orientation),
  and later `footnote`/`comment`/`trackedChange` (M6).
- Inline model: `text` runs carrying formatting flags:
  `{ bold, italic, underline, strikethrough, color, backgroundColor, fontFamily, fontSize, superscript, subscript }`.
- Table model: `{ cols, rows: string[][] }` plus cell-level formatting placeholders.
- Model document shape:
  ```js
  {
    title: string,
    blocks: Block[],
    pageFormat: 'a4'|'a5'|'letter'|'legal',
    fontFamily: string,   // default font
    updatedAt: number
  }
  ```
- Pure functions only: `normalizeModel(model)`, `emptyModel()`, `validateModel(model)`
  (throws on unknown node types — fail loud in dev, degrade in prod).

### 2. Serializers — `js/editor/html.js`
- `pagesToModel(pageEls: Element[]) → Block[]`
  - Walk each page's DOM; map `h1–h6` → `heading`, `p` → `paragraph`,
    `ul/ol/li` → `listItem` (with level), `img` → `image` (keep `src` data-URL),
    `a` → `link`, `table` → `table`, `.page-break` → `pageBreak`, `hr` → `horizontalRule`.
  - Flatten inline formatting into run objects: read inline `style` attributes
    (font-family, font-size, color, background-color), element tags (`b`, `strong`,
    `i`, `em`, `u`, `s`, `sub`, `sup`).
  - Strip pagination artifacts: `.page-break` handled as `pageBreak`; drop `data-split`
    attributes; drop `.unbreakable` wrapper semantics.
  - Merge adjacent runs with identical formatting.
- `modelToPages(model: Model) → Element[]`
  - Reverse mapping; emits clean HTML into fresh pages (no `data-split`).
  - Reuse `createPage()` from `js/editor/pagination.js` for page element construction.
- Unit-test both directions round-trip for a fixture of representative DOM.

### 3. Storage migration — `js/editor/document.js`
- New PouchDB doc shape (additive):
  ```js
  {
    _id: state.docId, title, author,
    model: Model,            // NEW
    content: string[],       // legacy page HTML, kept during transition
    offlineUse, pageFormat, fontFamily, updatedAt, synced
  }
  ```
- `loadContent()`: after loading a doc, if `doc.model` is missing but `doc.content`
  exists, derive the model via `pagesToModel` and persist it (migration write).
- `saveContent()`: serialize current pages through `pagesToModel` and store the model;
  keep writing `content` for rollback safety until M4.
- `renderDocument()`: prefer `doc.model` (via `modelToPages`); fall back to legacy
  `doc.content` path exactly as today.
- Preserve `handleDBChange()` behavior (`js/editor/document.js:330`) — remote docs
  without a model are migrated on load, never force-rendered.

### 4. Sync compatibility — `js/sync.js`
- No change to the sync protocol (still stores the PouchDB doc as-is).
- Add a sanity check in reconciliation: a doc with a `model` field syncs unchanged;
  legacy docs sync and migrate on the receiving end. No re-encryption changes
  (`@filen/sdk` encrypts the blob; the added field is transparent).

### 5. Round-trip safety net
- Before switching `renderDocument` to model-first, run the app against a set of
  documents: load → save → reload must produce identical visible output.
- Keep a dev-only console flag (`window.__scribenModelDebug`) to dump model JSON.

## Files touched
- `js/editor/model.js` (new)
- `js/editor/html.js` (new)
- `js/editor/document.js` (`saveContent`, `loadContent`, `renderDocument`)
- `js/editor/main.js` (import wiring)
- `js/sync.js` (verify only)

## Acceptance criteria
- Existing documents open identically before/after migration.
- `pagesToModel(modelToPages(x))` is a stable identity on a fixture corpus.
- New docs store a `model` in PouchDB; old docs migrate on first load.
- `npm run build` passes; no startup dependency added.
