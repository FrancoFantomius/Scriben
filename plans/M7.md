# M7 — Fidelity Hardening, Test Corpus, UX Polish

**Goal:** Close the program. Turn the fidelity matrix into a measured, enforced
contract; harden edge cases that M2–M6 surfaced; and polish the user experience of
importing/exporting so the flow feels native to Scriben.

## Context

The previous milestones each shipped with manual validation and spot fixtures. M7
systematizes: a repeatable golden-test corpus, deterministic round-trip checks, a
documented fidelity matrix, and the final UX pass (menu structure, progress states,
error handling, on-demand bundle budget).

## Tasks

### 1. Test harness — `tests/`
- Decide the runner: **no test framework is currently in `package.json`** — add a
  minimal harness to avoid a heavyweight dev dep. Recommendation: plain `node` script
  + `node:assert` using a DOM stub (`linkedom`) for the `html.js` round-trip tests;
  or, if CI budget allows, a small Playwright setup in `.github/workflows` for
  browser-level round-trips.
- Structure:
  ```
  tests/
  ├── fixtures/          # .docx generated in Word + LibreOffice
  ├── roundtrip.test.js  # export→import model-equality checks
  ├── html.test.js       # pagesToModel/modelToPages identity (M1)
  └── matrix.json        # authoritative fidelity matrix (source of README table)
  ```
- `npm test` wired into `package.json` (new script); `npm run build` stays untouched.

### 2. Deterministic round-trip checks
- Canonical form: normalize model JSON (sorted keys, stable run merging, stable
  annotation order) so `export→import` equality is order-independent.
- Assert per-fixture: `import(export(model(fixture))) ≡ model(fixture)` for the
  ✅ rows. Print a per-feature PASS/FAIL table; the build (`npm run build`) must not
  depend on tests, but CI should gate on them.
- Add a **repair invariant**: exported OOXML must not contain constructs that make
  Word show the "unreadable content" repair dialog (e.g. invalid rels, duplicate
  numbering ids, out-of-range indices). Tests open exports with a parser check
  (`jszip` schema-light validation) in CI.

### 3. Edge-case hardening (from earlier milestones)
- **Pagination × model:** paragraph split mid-run by pagination (`pagination.js`
  `data-split` clones) must collapse cleanly in `domToBlocks`; add fixtures where a
  footnote marker and an image sit at a page boundary.
- **Very large docs:** memory for Base64 images + OOXML DOM; add a size guard and a
  progress indicator (see UX below). Test a 500-page synthetic doc.
- **Invalid input:** malformed `.docx` (bad zip, missing parts, non-XML) → friendly
  error toast, no state corruption (state is only replaced after successful parse).
- **Repeated export stability:** export same doc twice → byte-identical zip (stable
  rels, timestamps fixed) so version-control diffs stay clean.
- **mammoth fallback (decide):** `ooxml.js` is the primary and only import engine.
  If `FALLBACK_TO_MAMMOTH` (M3) exists, evaluate in M7 whether it ever fired in
  corpus runs; if not, **remove mammoth entirely** — dependency and bundle both
  shrink and the fidelity matrix stays honest.

### 4. UX pass — `js/editor/compat.js` + `editor.html`
- **File menu restructure** (mirrors current items at `editor.html:70-106`):
  - *Open…* → `Open Word document (.docx)` (+ import warning if annotations exist)
  - *Download* → `Word document (.docx)`, keep `PDF (.pdf)`
  - `Save for offline use` unchanged.
- **Import flow:** drag-and-drop onto the workspace; a drop overlay; a progress bar
  for large files; a result toast listing warnings ("2 comments preserved", "1 table
  imported", "theme styles flattened to inline").
- **Export flow:** disabled button + spinner (pdf.js pattern), success toast with
  filename; keep the sanitize-filename logic (`pdf.js:82`).
- **Empty states:** importing an empty doc creates one blank page; exporting an empty
  doc still produces a valid `.docx`.
- **Settings:** nothing new persisted; imports default to current page format unless
  the source defines one (M5).

### 5. Documentation
- Update `README.md` (Features + Tech stack) and `CHANGELOG.md` with the compatibility
  feature set.
- Publish `plans/README.md` fidelity matrix as the living contract; `matrix.json` is
  the source of truth.

### 6. Bundle & performance budget
- Report gzip sizes of on-demand chunks: `docx`, `fflate` (and `mammoth` only if the
  M7 decide step keeps it). Keep the **critical path** at zero new deps — every
  converter loads on first use. Add `build:report` script (`vite build --report` or
  `rollup-plugin-visualizer`) and record a baseline in this file after M7 lands.

## Acceptance criteria
- `npm test` passes on the full corpus; CI runs it on push (workflow exists at
  `.github/workflows/deploy.yml` — add a test job).
- Fidelity matrix reflects reality for every row (no unverified ✅).
- No export produces a Word repair-prompt file across the corpus.
- Import of malformed files never corrupts the active document.
- UX flows (open/download/drag-drop) complete without console errors and with visible
  progress + warning toasts.
- **Program definition of done:** every milestone plan's acceptance criteria met,
  matrix fully green on the supported rows, annotations preserved on round-trip.
