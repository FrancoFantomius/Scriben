# M3 — DOCX Import (Word → Scriben, primary OOXML reader)

**Goal:** Open a `.docx` file in Scriben and render it for editing. The import engine
is a **hand-rolled OOXML reader** (`js/editor/ooxml.js`) that reads the DOCX zip
directly — not mammoth. This milestone delivers the full import pipeline end to end:
ZIP/XML plumbing, a core body walker, run/paragraph property parsing, text & runs,
links, images, page setup, structured warnings, and the UI wiring that lets a user
open a `.docx` and edit it in place.

## Why not mammoth

`mammoth`'s own documentation states it is **not designed to convert complex
documents**; it works best on files that use Word's default styles consistently, and
it drops comments, tracked changes, most styles/themes, section breaks,
headers/footers, and precise numbering. Those are precisely the features this program
must round-trip. Relying on mammoth as the foundation would lock in a fidelity ceiling
and force a rewrite of the import engine exactly where the program's hardest
requirements arrive (M5/M6). So M3 builds the OOXML reader directly; mammoth is
kept only as an optional last-resort fallback behind a flag (and is a candidate for
removal in M7 if it earns no keep).

## Definitions & invariants

- **Namespace constants** (single source, `js/editor/ooxml.js`):
  - `w` = `http://schemas.openxmlformats.org/wordprocessingml/2006/main`
  - `r` = `http://schemas.openxmlformats.org/officeDocument/2006/relationships`
  - `a` = `http://schemas.openxmlformats.org/drawingml/2006/main`
  - `wp` = `http://schemas.openxmlformats.org/drawingml/2006/wordprocessingDrawing`
  - `pic` = `http://schemas.openxmlformats.org/drawingml/2006/picture`
  - `mc` = `http://schemas.openxmlformats.org/markup-compatibility/2006`
  - `w14` = `http://schemas.microsoft.com/office/word/2010/wordml`
  - `cp` (core properties) = `http://schemas.openxmlformats.org/package/2006/metadata/core-properties`
  - `dc` (dc:title) = `http://purl.org/dc/elements/1.1/`
- **Units:** OOXML lengths are twips (1/20 pt) for `w:pgSz`/margins/indents,
  half-points for `w:sz`, EMUs (914400/inch) for drawing extents. Convert once,
  early, and never carry raw values out of the parsing layer.
- **Failure policy:** the walker never throws for unexpected XML. Unknown nodes are
  skipped with a structured warning; only a structurally unreadable package
  (bad zip / missing `word/document.xml`) raises a user-facing error.
- **Determinism:** output model is produced in document order; identical input bytes
  always produce an identical model (needed by M4/M7 round-trip tests).

## Architecture

```
file (File)                        docxImport.js
   │ readAsArrayBuffer                  │ importDocx()
   ▼                                    ▼
ArrayBuffer ──▶ unzip (fflate) ──▶ Parts map ──▶ OOXMLReader.walk()
                                                     │
                                     ┌───────────────┼──────────────────┐
                                     ▼               ▼                  ▼
                             text/format       links/images      page setup
                                     │               │                  │
                                     └───────▶ model blocks + warnings
                                                     │
                                                     ▼
                                        renderDocument(model) → pages
```

- `ooxml.js` — pure parsing: `Parts` loader + `walkBody(doc) → { blocks, warnings, meta }`.
  No DOM, no `state` imports, no side effects. Unit-testable in isolation.
- `docxImport.js` — orchestration + side effects: lazy lib loading, file I/O,
  title extraction, calling `renderDocument`, `saveContent`, toast plumbing.
- `compat.js` — UI only: menu item, hidden file input, drag-drop overlay.

## Tasks

### T1. ZIP + XML plumbing — `js/editor/ooxml.js`

#### T1.1 ZIP part enumeration
- Add `fflate` to `package.json` dependencies (`^0.8.x`), loaded lazily via
  `import('fflate')` in `ensureOoxmlLib()` (see T7).
- `unzipParts(buffer: Uint8Array) → Promise<Map<string, Uint8Array>>`:
  - `fflate.unzipSync(new Uint8Array(await file.arrayBuffer()), { filter: (f) => !f.name.endsWith('/') })`
    — decode all entries; keys are the normalized part names (e.g.
    `word/document.xml`).
  - Reject with `{ code: 'INVALID_ZIP' }` on throw; reject with
    `{ code: 'MISSING_DOCUMENT' }` if `word/document.xml` absent.
- Expose on the reader: `parts: Map<string, Uint8Array>`, and helpers:
  - `getPart(path) → Document|null` — decode UTF-8, `new DOMParser().parseFromString(xml, 'application/xml')`,
    null on parse error (warn `XML_PARSE_ERROR`, include `path`).
  - `getBytes(path) → Uint8Array|null`
  - `listParts(/^word\/(media|embeddings|charts)\//) → string[]`
- Guard: strip part names of any leading `/` and reject `..` path traversal so a
  hostile zip cannot escape the parts map.

#### T1.2 Namespace-aware XML helpers
- `child(el, localName)`, `children(el, localName)`, `childNS(el, ns, localName)`,
  `attr(el, qName)`, `attrNS(el, ns, localName)`, `text(el)`.
  - Use `el.getElementsByTagNameNS(wNS, localName)` for descendant search;
    never `getElementsByTagName` (unprefixed or misprefixed OOXML breaks it).
  - `attr` must handle the **prefixed-qualified** attribute names exactly as stored,
    e.g. `w:val` → `el.getAttribute('w:val')` (Word always writes the `w` prefix;
    do not assume namespace-based attribute lookup).
- `firstChildNamed` + `text` must treat whitespace-only text as empty.
- Namespaces are resolved at the parse level; strip nothing, keep text verbatim
  (`xml:space="preserve"` runs must not be trimmed — see T3).

#### T1.3 Relationship map
- `parseRels(doc) → Map<string, { target, mode? }>`:
  - From `word/_rels/document.xml.rels`: each `<Relationship Id="rId5"
    Type=".../hyperlink|.../image" Target="..." TargetMode="External"/>`.
  - Key by `Id`. If the part is missing, return an empty map (warn
    `MISSING_RELS` once); broken rels resolve to `null` and are handled per consumer.

#### T1.4 Title metadata
- `getCoreTitle() → string|null`: parse `docProps/core.xml` if present; read
  `dc:title` (namespace `dc`); if absent, `w:title` in `docProps/app.xml`. Fallback
  to `null` (caller uses current document title).

### T2. Core body walker — `js/editor/ooxml.js`

#### T2.1 Iteration contract
- `walkBody(bodyEl: Element, ctx: { parts, rels, warnings }) → Block[]`
- Iterate `children(bodyEl, 'p' | 'tbl' | 'sectPr' | 'bookmarkStart' |
  'bookmarkEnd' | 'ins' | 'del' | 'sdt')` **in document order** (use
  `Array.from(bodyEl.childNodes)` and switch on `localName` to preserve order).

Handler table:

| `localName` | Action this milestone |
|---|---|
| `p` | `parseParagraph` (T3) → block |
| `tbl` | `deferTable` → emit warning `TABLE_DEFERRED`, **skip content** (no partial table) |
| `sectPr` | `parseSectPr` (T6) → update `meta.pageSetup`; do **not** emit a block (no sections until M5) |
| `bookmarkStart` | register target name → id in `meta.bookmarks` map (for internal links, T5) |
| `bookmarkEnd` | no-op (validates pairing; warn `UNPAIRED_BOOKMARK` if missing start) |
| `ins` / `del` | `deferTrackedChange` → extract plain text as runs (stripped of change marks), warn `TRACKED_CHANGE_DEFERRED` |
| `sdt` | unwrap: walk children of `w:sdtContent` as if siblings (structured doc tags) |
| `customXml` | skip + warn `CUSTOM_XML_SKIPPED` |

#### T2.2 Text node boundaries
- A paragraph's text comes from `w:r/w:t`, `w:hyperlink/w:r/w:t`,
  `w:ins/w:r/w:t`, and `w:sdt/w:sdtContent/...`. The walker must collect runs from
  all these containers in order. Centralize in `collectRuns(paragraphEl) →
  Array<{ el, type: 'run'|'hyperlink'|'ins'|'del' }>` so T3/T4/T5 share one code path.
- `w:proofErr`, `w:bookmarkStart`, `w:commentRangeStart` are **not** runs — skip
  silently.

### T3. Paragraphs, runs, text, formatting — `js/editor/ooxml.js`

#### T3.1 Paragraph properties (`w:pPr`)
Parse `pPr` (may be absent → default) into a plain object:

| `w:pPr` child | Output |
|---|---|
| `w:jc` `w:val` | `alignment: 'left'\|'center'\|'right'\|'both'\|'distribute'` → model `align` (`justify` maps to `'both'`); unknown → warn `UNKNOWN_ALIGNMENT`, default `left` |
| `w:ind` `w:left`/`w:right`/`w:firstLine` (twips) | `indentLeft`/`indentRight`/`firstLine` in pt (÷20) |
| `w:spacing` `w:before`/`w:after`/`w:line` (twips) | `spaceBefore`/`spaceAfter`/`lineSpacing` in pt; `w:lineRule="exact"`/`"atLeast"` kept as `lineRule` |
| `w:pStyle` `w:val` | `styleId` (kept; resolution is M5) |
| `w:numPr` (`w:ilvl`, `w:numId`) | `list: { numId, level }` raw; full resolution (numbering.xml) is M5, but M3 maps to a **basic** `listItem { listType: 'bullet'|'number', level }` by reading `numbering.xml` if present (best effort) — see T8 |
| `w:keepNext` / `w:keepLines` | `keepNext: true` / `keepLines: true` (stored, not rendered) |
| `w:pageBreakBefore` | emit `pageBreak` block **before** the paragraph |
| anything else | ignore silently |

- A `p` whose runs are all empty and has no `pPr` beyond defaults → emit an **empty
  paragraph** block (keeps paragraph structure / vertical rhythm). Never collapse two
  adjacent empty paragraphs.

#### T3.2 Run properties (`w:rPr`)
Parse into a run-props object (inputs are children of `w:rPr`):

| Child | Value handling |
|---|---|
| `w:b`, `w:bCs` | `bold` = `true`; **unless** `w:val="false"`/`"0"` → `false` (explicit off overrides style — required for correctness, see M5) |
| `w:i`, `w:iCs` | `italic`, same `w:val` rule |
| `w:u` `w:val` | `underline`; `val="none"` → `false`; `val="single"`/`"words"` → `true`; double/dotted stored as `underlineStyle` |
| `w:strike`, `w:dstrike` | `strikethrough` = `true` (dstrike too) |
| `w:color` `w:val` | `color`; `val="auto"` → omit (use default); parse `#RRGGBB`; theme refs (`w:themeColor`) → keep placeholder for M5 |
| `w:shd` `w:fill` | `backgroundColor` = `#RRGGBB`; `fill="auto"` → omit |
| `w:sz` `w:val` (half-points) | `fontSizePt` = `val / 2`; range-clamp 1–1638 |
| `w:szCs` | complex-script size — ignore unless > `w:sz` (then use it) |
| `w:rFonts` `w:ascii`/`w:hAnsi`/`w:cs`/`w:eastAsia` | `fontFamily` = ascii (fallback hAnsi, then cs); `eastAsiaFont` stored separately |
| `w:vertAlign` `w:val="superscript"`/`"subscript"` | `superscript`/`subscript` |
| `w:highlight` `w:val` | `highlight` (named color, e.g. `yellow`) → map to `backgroundColor` via small lookup; unknown → warn |
| `w:rStyle` | `styleId` kept for M5 |
| anything else (spacing, kern, lang…) | ignore silently |

- **Property precedence within a run:** direct children of `w:rPr` are authoritative
  for M3 (styles.xml resolution is M5). No inheritance logic this milestone.
- `w:val="false"` handling must be implemented even though most docs omit it —
  Word emits explicit-off on mixed selections; without it bold/italic would leak.

#### T3.3 Text extraction
- `w:t` → `text()` verbatim; **preserve whitespace** when the nearest ancestor has
  `xml:space="preserve"` (check the run's `w:t` attribute itself, else paragraph).
- `w:tab` → `\t` in the run text.
- `w:br`:
  - no `w:type` (or `w:type="textWrapping"`) → `\n` (soft break → Scriben `<br>`).
  - `w:type="page"` → flush current run, emit a **`pageBreak` block**, continue.
- `w:cr` → `\n`.
- `w:noBreakHyphen` → `\u2011`.
- `w:softHyphen` → `\u00AD`.
- `w:lastRenderedPageBreak` → **ignore** (render artifact, not a page break).
- `w:footnoteReference` / `w:endnoteReference` → emit a `footnoteRef` marker run
  (raw `{ id }`); the footnote bodies themselves are M6. Warn `FOOTNOTE_DEFERRED`.

#### T3.4 Run splitting & merging
- For each logical run, produce one or more model runs:
  - Split at formatting **boundaries** only (a `w:r` element is a single model run;
    different `w:r` elements with identical props merge).
  - Split text at `\n` for soft breaks (each segment a `text` run, `\n` becomes a
    `<br>` run).
  - Split at `\t` (tab run).
- After collecting all runs for a paragraph, **merge adjacent runs** with identical
  formatting + consecutive text (reuse M1's `mergeRuns` helper from `html.js`).
- Empty runs (no text, no image, no break) are dropped.

#### T3.5 Emit paragraph block
```
{ type: 'paragraph', align, indentLeft?, indentRight?, spaceBefore?, spaceAfter?,
  keepNext?, runs: [ TextRun|BreakRun|TabRun|LinkRun|ImageRun|FootnoteRefRun ] }
```
- Headings: if `w:pStyle` resolves to a known heading style id via a **minimal
  built-in map** (`Heading1..Heading6`, `Title` → `heading` level 1..6 / `title`
  block). Full style resolution stays in M5. Unknown styles → `paragraph`.
- `w:outlineLvl` in `w:pPr` (`w:val="0".."8"`) also maps to `heading` level+1
  (cheap, reliable heading detection).

### T4. Images — `js/editor/ooxml.js`

- Detect in a run's children: `w:drawing` (modern) or `w:pict`/`w:object` (legacy).
- Modern path (`w:drawing`):
  1. `wp:inline | wp:anchor` → extents via `wp:extent cx/cy` (EMUs).
  2. `a:blip r:embed="rIdN"` → `rels.get(rIdN)` → media path (e.g.
     `word/media/image3.png`).
  3. Handle `r:link` (external image) → warn `EXTERNAL_IMAGE`, skip.
- Legacy path (`w:pict`/`w:object`): `v:imagedata r:id` → same rels resolution;
  extents via `v:shape style="width:...;height:..."` parsed from the style string
  (`pt`/`px` units) — warn `LEGACY_IMAGE` but still import.
- `getBytes(mediaPath)` → Base64: `btoa` over a UTF-8-safe byte string built with
  `String.fromCharCode(...chunk)`. Use chunking (e.g. 0x8000) to avoid stack issues
  on large images.
- **MIME / extension:** from the media path suffix (`png`, `jpg`/`jpeg`, `gif`,
  `bmp`, `svg`). Build `data:<mime>;base64,...`. Unknown extension → sniff magic
  bytes (PNG `\x89PNG`, JPEG `\xFF\xD8`, GIF `GIF8`); else `application/octet-stream`.
- **Size:** EMU → px: `px = emu / 914400 * 96`; round to 1 decimal. Store
  `width`/`height`. Cap sanity: if a dimension is absurd (> 40 000 px) warn
  `IMAGE_SIZE_UNUSUAL` and fall back to the image's natural size (deferred — natural
  size requires decoding; M3 uses the extent as-is).
- Model node: `{ type: 'image', src: dataUrl, width?, height? }`, emitted as its own
  paragraph run.
- **No canvas re-encoding.** Bytes are copied verbatim; no image decoding ever happens
  in M3 (privacy + fidelity + avoids CORS/taint issues).

### T5. Links — `js/editor/ooxml.js`

- `w:hyperlink` child of a paragraph:
  - `r:id` present → external: `rels.get(id)` → `target`; if `mode === 'External'`
    keep as-is; if rel missing → warn `LINK_TARGET_MISSING`, emit plain text runs.
  - `w:anchor` present → internal: target = anchor name; if it matches a registered
    `bookmarks` entry → `{ type:'link', internal:true, target }`, else warn
    `LINK_ANCHOR_MISSING` and emit as plain text.
  - Both present → external wins (Word treats `r:id` as primary).
- Model run: `{ type: 'link', href, internal?: true, runs: TextRun[] }` — the link
  wraps child text runs parsed with T3.2/T3.3.
- `mailto:` URLs pass through unchanged.

### T6. Page setup — `js/editor/ooxml.js`

- From the **first** `w:sectPr` encountered (walk in order; the body's trailing
  `w:sectPr` is the primary one for single-section docs — prefer the last
  body-level `w:sectPr` if multiple exist, matching Word semantics):
  - `w:pgSz w:w` / `w:w` + `w:h` (twips) → mm: `mm = twips * 25.4 / 1440`
    (1440 twips/inch).
  - `w:orient="landscape"` → swap width/height, set `orientation`.
- Classify against Scriben presets (tolerance ±1 mm):
  | mm (w×h) | format |
  |---|---|
  | 210×297 | a4 |
  | 148×210 | a5 |
  | 215.9×279.4 | letter |
  | 215.9×355.6 | legal |
  | anything else | `custom` |
- Output `meta.pageSetup = { format, orientation, widthMM, heightMM, margins: { top, bottom, left, right } }`.
- `docxImport.js` sets `state.currentDoc.pageFormat = format` (or keeps current if
  `custom`) before render. Exact custom-mm round-trip is M5; margins are stored in
  `meta` for M5.

### T7. Import API & orchestration — `js/editor/docxImport.js`

```
async ensureOoxmlLib()      // lazy import('fflate'); also conditional mammoth
async importDocx(file)      // full pipeline, returns ImportResult
function buildWarnings(list) // [{ code, message, at?: { block, index } }]
```

`importDocx(file) → Promise<{ blocks, pageFormat, orientation, title, warnings }>`:
1. `file.arrayBuffer()` → `Uint8Array`.
2. `unzipParts(...)` → parts map (throws `INVALID_ZIP` / `MISSING_DOCUMENT`).
3. `parseRels(document.xml)` → rels.
4. `getPart('word/document.xml')` → `walkBody(...)` → blocks + meta.
5. `getCoreTitle()` → title (nullable).
6. Assemble `ImportResult`.

- `FALLBACK_TO_MAMMOTH = false` (const): if enabled, wrap steps 2–4 in try/catch;
  on failure `mammoth.convertToHtml` → parse HTML with `domToBlocks` (from M1
  `html.js`) and add a `FALLBACK_USED` warning. Disabled by default; re-evaluated in
  M7.
- All thrown errors carry a `code` (`INVALID_ZIP`, `MISSING_DOCUMENT`,
  `XML_PARSE_ERROR`) so the UI can localize messages.

### T8. Basic list best effort — `js/editor/ooxml.js`

- If `word/numbering.xml` exists: parse `w:num → w:abstractNumId` and
  `w:abstractNum/w:lvl[0]` → `w:numFmt` (`bullet` → bullet, else number) + `w:start`.
- For each paragraph with `w:numPr`, look up `numId → numFmt/start`; emit
  `listItem { listType, level, start }` for level 0 only (nested level grouping is
  M4). `start` captured for `start≠1` numbered lists.
- `numbering.xml` missing → warn `NUMBERING_DEFERRED`, emit paragraphs with a
  `list: { numId, level }` hint (treated as plain paragraphs; M5 resolves fully).

### T9. Warning taxonomy — `js/editor/ooxml.js`

Centralize as constants + a `warn(ctx, code, detail)` helper. Every code has a stable
`message` string used by toasts/tests.

| Code | Meaning |
|---|---|
| `INVALID_ZIP` | not a zip / corrupt package |
| `MISSING_DOCUMENT` | `word/document.xml` absent |
| `XML_PARSE_ERROR` | a part failed to parse as XML |
| `MISSING_RELS` | rels part missing |
| `TABLE_DEFERRED` | table skipped (M5) |
| `TRACKED_CHANGE_DEFERRED` | `w:ins`/`w:del` flattened to plain text (M6) |
| `FOOTNOTE_DEFERRED` | footnote ref kept, body ignored (M6) |
| `CUSTOM_XML_SKIPPED` | `w:customXml` dropped |
| `NUMBERING_DEFERRED` | numbering.xml missing; lists flattened |
| `UNPAIRED_BOOKMARK` | bookmarkStart without end |
| `LINK_TARGET_MISSING` | hyperlink rel id unresolved |
| `LINK_ANCHOR_MISSING` | internal anchor with no bookmark |
| `EXTERNAL_IMAGE` | image linked externally, skipped |
| `LEGACY_IMAGE` | VML image imported (best effort) |
| `IMAGE_SIZE_UNUSUAL` | drawing extent implausible |
| `UNKNOWN_ALIGNMENT` | `w:jc` value unrecognized |
| `UNKNOWN_STYLE` | `w:pStyle` not in built-in map |
| `FALLBACK_USED` | (opt-in) mammoth path served |

### T10. UI wiring — `js/editor/compat.js` + `editor.html` + `js/editor/main.js`

- **Menu item:** add `menu-import-docx` under File (`editor.html:70-106`),
  icon `upload_file`, label `Open Word document (.docx)`.
- **File input:** hidden `<input type="file" id="docx-file-input" accept=".docx">`
  appended in `compat.js`; `menu-import-docx` click → `input.click()`.
- **Drag & drop:** on `state.container` (and window fallback): `dragover` shows a
  full-screen `.drop-overlay` (`preventDefault` + set `dataTransfer.dropEffect =
  'copy'`); `drop` → `e.dataTransfer.files[0]`, validate name ends `.docx` (else
  toast `Not a .docx file`), clear overlay.
- **Flow after `importDocx` resolves:**
  1. `state.currentDoc.title = result.title || existing title`; set the
     `#document-title` input.
  2. `applyPageFormat(result.pageFormat)` (skip if `custom`).
  3. Replace content: `state.container.innerHTML = ''`, render via
     `renderDocument({ ...state.currentDoc, content: [] })` after stashing the model
     into `state.currentDoc.model` (M1 storage).
  4. `paginate()` then `saveContent()`.
  5. Toast: `Imported "title"` + per-warning line (max 5, then `and N more`).
- **Error toast:** on thrown `code`, show `Could not open file: <message>`.
- `initCompat()` called from `main.js`'s `DOMContentLoaded` (mirrors
  `initPdfExport` wiring at `pdf.js:97`). Do **not** auto-load fflate at init.

## Acceptance criteria

- A `.docx` from Word opens in Scriben, is editable in place, and persists via PouchDB.
- Text, bold/italic/underline (incl. explicit `w:val="false"`), colors, sizes, fonts,
  headings, alignment, basic bullet/numbered lists, external + internal links, and
  inline images survive — **without mammoth**.
- Page format derives from `w:pgSz`; landscape handled.
- Every unsupported construct in `complex.docx` produces the exact warning code from
  the taxonomy; a corrupt zip produces `INVALID_ZIP` and **never** corrupts the
  active document (content replaced only after a successful parse).
- Parsing is deterministic: same bytes → same model (assert in a headless smoke test
  with `linkedom`).
- fflate loads only on first import; app startup bundle is unchanged.
