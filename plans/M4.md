# M4 — Round-Trip: Lists, Links, Images

**Goal:** Make the three most content-critical features survive
export → Word → (edit) → import → export without degradation: bullet/numbered lists,
hyperlinks, and embedded images. This is the first milestone that closes the full loop
and is where the fidelity matrix gets its first measured rows.

## Context

- Lists: Scriben creates them via `execCommand` → `<ul>/<ol><li>` (arbitrary nesting).
  Word uses `w:numPr` referencing abstract numbering definitions — the classic
  round-trip loss point. The M3 OOXML reader resolves `w:numPr` against
  `numbering.xml` (numFmt, start, level) so nesting/type survive.
- Links: Scriben stores `<a href>` via `createLink` (`js/editor/modals.js`);
  Word uses `w:hyperlink` + `word/_rels/document.xml.rels`.
- Images: Scriben embeds inline Base64 `<img>`; Word stores binaries in
  `word/media/` referenced by `r:embed`.

## Tasks

### 1. Normalize lists in the model — `js/editor/html.js`
- Change `listItem` to carry `{ listType: 'bullet'|'number', level: number, start? }`.
- `domToBlocks`: parse nested `<ul>/<ol>` recursively and assign levels;
  strip `data-split` remnants.
- `modelToPages`: rebuild `<ul>/<ol>` nesting from `level`, preserving list type and
  `start` for numbered lists (Word's `w:start`).

### 2. Lists → OOXML — `js/editor/docxExport.js`
- Use `docx` `Numbering` + `Levels` (bullets: `bullet` symbol; numbers: `decimal`).
- Register one numbering per list type with up to N levels (N = max observed depth).
- `listItem` → `Paragraph` with `numbering: { reference, level }`.
- `start` → first-level `w:start` override.

### 3. Lists ← OOXML — `js/editor/ooxml.js` (reader extension)
- Resolve each paragraph's `w:numPr` (`w:numId` + `w:ilvl`) through `numbering.xml`
  to the abstract numbering's `w:numFmt` (bullet/decimal/lowerLetter), `w:start`,
  and indent — then emit `listItem { listType, level, start }`.
- Group consecutive same-list paragraphs into one logical list; degrade gracefully
  (flat list) when `numbering.xml` is missing or malformed.

### 4. Links — export
- `link` block / inline run → `Paragraph.children: [new ExternalHyperlink({ children: [TextRun], link: href })]`.
- Collect hrefs into a `Hyperlink` map so `docx` emits the rels correctly.
- Internal anchors (`#...`) → bookmark links if present in the model; else plain text.

### 5. Links — import
- The M3 reader resolves `w:hyperlink` (`r:id` → `document.xml.rels` URL, or
  `w:anchor` → bookmark target) to `link` runs.
- Mark anchor-only links `{ internal: true }` so export emits `w:anchor` bookmarks
  rather than a broken URL.

### 6. Images — export
- `image` block → `Paragraph({ children: [ImageRun] })` from the data-URL bytes.
- Set width/height to Scriben's displayed size (read from the `<img>` natural/drawn
  dims at save time — extend the M1 `image` node with `width`/`height`).
- `docx` writes `word/media/` + rels automatically; verify relationship ids are stable
  across repeated exports (deterministic order).

### 7. Images — import
- The M3 reader converts `word/media/*` binaries to Base64 data-URLs (Scriben model)
  and records `width`/`height` from `wp:extent`. M4 verifies these dims match the
  original drawing size and that bytes are untouched.

### 8. Image compression guard
- Base64 images in PouchDB bloat docs; add a soft cap (e.g. warn > 5 MB) and document
  it. Do not re-encode in M4 (no canvas round-trip; preserves quality + privacy).

### 9. Golden tests — first corpus
- `tests/fixtures/*.docx` generated in Word + LibreOffice covering:
  nested bullets/numbers with `start`, external + anchor links, inline images at
  known sizes.
- Assert (dev-only harness, run via `node` + a DOM stub, or Playwright if added):
  export→import produces an identical model on the fixture set (lists/links/images
  keys compared structurally).

## Files touched
- `js/editor/html.js` (list normalization, image dims)
- `js/editor/model.js` (listItem/image schema additions)
- `js/editor/docxExport.js` (Numbering, Hyperlink, ImageRun)
- `js/editor/ooxml.js` (list resolution, link targets, image dims)
- `tests/fixtures/` (new)

## Acceptance criteria
- Export a Scriben doc with nested lists, links, images → open in Word → save → import
  back: lists keep nesting/type, links stay live, images keep size and bytes.
- A `start=5` numbered list still starts at 5 after round-trip.
- Images are not rasterized or re-encoded anywhere in the pipeline.
- Fidelity matrix rows for lists/links/images marked ✅ with a passing golden test.
