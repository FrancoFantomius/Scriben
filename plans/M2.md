# M2 — DOCX Export (Scriben → Word)

**Goal:** Export the canonical model to a `.docx` that Microsoft Word opens cleanly,
covering text, rich formatting, fonts, alignment, page setup, and manual page breaks.
Depends on M1 (model exists).

## Approach

Use the on-demand `docx` npm library (client-side OOXML generator). Load it lazily
exactly like `pdf.js:17` does with html2canvas/jspdf. No new startup dependency.

## Tasks

### 1. On-demand loader — `js/editor/docxExport.js`
- Reuse/extract the `loadScript()` helper from `js/editor/pdf.js:3`.
- `ensureDocxLib()` loads a bundled `docx` build from `node_modules`
  (`import()` of `docx` works under Vite; prefer ESM dynamic import to avoid CDN).
  Fallback to CDN only if bundling is problematic.
- Expose `exportDocx()` + `initDocxExport()` mirroring `pdf.js`'s
  `generatePdf()` / `initPdfExport()` structure.

### 2. Model → OOXML mapping — `js/editor/docxExport.js`
- **Document root:** `new Document({ sections, styles })`.
- **Page setup** from `state.currentDoc.pageFormat` (`js/editor/state.js:11`):
  map to `PageSize` + `PageMargin` (A4 210×297mm, Letter 215.9×279.4, Legal
  215.9×355.6, A5 148×210 — same table as `pdf.js:36`).
- **Blocks:**
  - `paragraph`/`heading` → `Paragraph` with `heading: HeadingLevel` for headings.
  - `horizontalRule` → `Paragraph` with bottom border.
  - `pageBreak` → `Paragraph({ children: [new PageBreak()] })`.
  - Run properties: bold/italic/underline/strikethrough, `color` → `Color`,
    `backgroundColor` → `Shading`, `fontFamily`/`fontSize` → `TextRun({ font, size })`.
  - Alignment → `Paragraph.alignment` (left/center/right/justify).
  - Superscript/subscript → `TextRun({ superScript/subScript })`.
- **Font mapping table** `fonts.json` → Word-family names:
  - Self-hosted fonts (Montserrat, Playfair Display, Nunito, Oswald, …) are not
    installed in Word by default — map to closest system equivalents, e.g.
    Noto Sans → Calibri/Helvetica, Montserrat → Century Gothic,
    Google Sans → Arial, Playfair Display → Georgia, Oswald → Arial Narrow.
  - System fonts (Arial, Georgia, Times New Roman, Calibri) pass through by name.
  - The mapping is a single exported function `mapFontToWord(name)` so M5 can reuse it.
- **Default style:** set `styles.default` font to the doc's `fontFamily` (mapped),
  matching `applyFontFamily` in `js/editor/ui.js`.
- **Title:** ignore for now (Word documents don't carry a visible title; M4 wires
  it to document metadata).

### 3. Section breaks (placeholder)
- Single section per document in M2 (page format is global in Scriben today).
- Reserve the model `section` node for M5.

### 4. Wiring — `js/editor/compat.js` + `editor.html`
- Add `menu-export-docx` item to the File dropdown (`editor.html:97` area),
  next to "Export as PDF".
- `initCompat()` binds it to `exportDocx()` with the same disabled/icon spinner
  pattern as `pdf.js:101`.
- Filename from `#document-title` sanitized exactly as `pdf.js:82` does.

### 5. Manual validation
- Open exported files in Microsoft Word and LibreOffice Writer; verify:
  - fonts/colors/alignment render as mapped;
  - page size matches the active page format;
  - manual page breaks land where the `.page-break` was;
  - text remains selectable/editable (i.e., we never rasterize).

## Files touched
- `js/editor/docxExport.js` (new)
- `js/editor/compat.js` (new — shared menu/file wiring used by later milestones)
- `editor.html` (File menu item)
- `js/editor/main.js` (initCompat import + call)

## Acceptance criteria
- A formatted Scriben doc exports to `.docx` opening without repair prompts in Word.
- Bold/italic/underline, colors, fonts (mapped), sizes, alignment, headings,
  page breaks, and page size all round-trip into Word.
- PDF export path is untouched and still works.
- Library loads on demand (first click shows the spinner; app start has no new deps).
