# M5 — Tables, Headers/Footers, Sections, Styles & Themes (reader extensions)

**Goal:** Extend the M3 OOXML reader from "core body walker" to the constructs it
stubbed or deferred: tables, headers/footers, page numbers, section breaks, precise
page setup, and best-effort paragraph/character styles + themes. Export is upgraded
to match. No mammoth involvement — the reader is the only import engine.

## Why a reader, not a converter

The core walker already exists (M3). This milestone is purely additive: each task
extends `ooxml.js` and adds the corresponding model node + export path. `docx`
remains the export engine; `ooxml.js` is the import engine. Scope boundary from the
program README applies: styles/themes resolve to **inline** formatting (Scriben has
no style system), and headers/footers render as non-editable page chrome.

## Tasks

### 1. Tables — `js/editor/ooxml.js` + model + export
- Import: `w:tbl` → model `table` block (rows × cells). Handle `w:tc` merging via
  `w:gridSpan` / `w:vMerge` (flagged on the cell; full resolution best-effort),
  cell `w:tcPr` (shading, borders), `w:tblPr` (table width, alignment).
- Render: Scriben already treats `TABLE` as an unbreakable node
  (`pagination.js:143`), so an imported table renders as one page-level block.
- Export: `docx` `Table`/`TableRow`/`TableCell` from the model table block, emitting
  `w:tblBorders` + per-cell `w:shd` + `w:gridSpan`/`w:vMerge` when flagged.

### 2. Numbering — full resolution
- Parse `numbering.xml`: `w:num → w:abstractNumId`; per-level `w:numFmt`,
  `w:start`, `w:ind` (left/indent). Cache the map once per import.
- Feed `numPr` resolution to the M4 list logic; emit `{ listType, level, start }`.

### 3. Styles & themes — best effort
- Parse `styles.xml`: `w:docDefaults`, paragraph/character `w:style` with
  `w:basedOn` + `w:next` chains.
- Style resolver: resolve each run/paragraph's effective properties by walking the
  `basedOn` chain, apply docDefaults, then let direct (inline) formatting win.
- Emit resolved values as **inline** formatting in the model — this is the `▶ inline`
  row of the fidelity matrix (Scriben has no style system yet).
- Themes (`word/theme/theme1.xml`): resolve `w:themeColor`/`w:themeShade` against the
  theme's color map; fall back to the document's default colors.

### 4. Headers, footers, page numbers, sections
- Model gains a `section` block `{ pageFormat, orientation, header: Block[],
  footer: Block[], pageNumbering: boolean, margins }`; the document-level
  `pageFormat` becomes the first section's setup (M1 model stays compatible).
- Import: follow `w:sectPr` → `w:headerReference`/`w:footerReference` → parse those
  parts with the same body-walker code → attach to the section. Detect `w:pgNumType`.
- Export: `docx` `Header`/`Footer` (incl. `PageNumber.Current`) per section; emit
  `SectionProperties` per model `section`.
- Render: pagination renders headers/footers as fixed page chrome (non-editable
  overlay divs) — **visual only**; editing headers is out of scope.

### 5. Precise page setup
- Resolve `w:pgSz`/`w:pgMar` exactly (not nearest format): store exact mm on the
  section so export returns the original size. Scriben's fixed A4/Letter/etc. presets
  remain the only *selectable* sizes; imported custom sizes display as "Custom".
- Wire import to set `state.currentDoc.pageFormat` from the first section
  (replaces M3's nearest-format mapping).

### 6. Regression guard
- Re-run the M4 golden corpus through the extended reader; results must match or
  exceed the M4 baseline on lists/links/images and add tables, headers/footers,
  and page size as new passing rows.
- The M3 walker's "defer + warn" behavior must remain for anything still unknown
  (e.g. text boxes, SmartArt) — never a crash.

## Files touched
- `js/editor/ooxml.js` (tables, styles/themes, numbering, headers/footers, sections)
- `js/editor/model.js` (section/table schema extensions, exact page size)
- `js/editor/docxExport.js` (sections, tables, headers/footers, page numbers)
- `js/editor/html.js` (render sections, tables, header/footer chrome)
- `js/editor/pagination.js` (header/footer overlay integration)
- `editor.html` (page format dropdown gains "Custom" read-only display)

## Acceptance criteria
- Import a Word doc containing a table, header/footer, page numbers, and section
  breaks: all render in Scriben; re-export opens in Word with table borders,
  header/footer text, page numbering, and page size preserved.
- Paragraph/character styles resolve to visually-equivalent inline formatting.
- Docs with custom page sizes import as "Custom" and export back at the exact size.
- The M4 golden corpus still passes; tables/headers/footers/page-size add new
  passing rows to the matrix.
