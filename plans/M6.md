# M6 — Footnotes, Comments, Tracked-Change Preservation

**Goal:** Handle the three Word-only annotation constructs. Per the program decision:
footnotes and comments are **viewable and preserved** (not authored inline); tracked
changes are **preserved** so a save → re-export doesn't destroy them. Full inline
authoring (inserting comments, accept/reject changes) is explicitly out of scope and
would require replacing the `contenteditable` surface.

## Scope boundary (read first)

Scriben's editor is `contenteditable` + `document.execCommand`
(`js/editor/pagination.js:289`, `js/editor/commands.js:75`). It cannot render
authoring UI for comments or accept/reject tracked changes. So:

- **Preservation** (model stores the annotations; export writes them back) — in scope.
- **Viewing** (footnote panel, comment sidebar) — in scope.
- **Authoring/accepting/rejecting** — out of scope, documented as a separate project
  (likely a ProseMirror/Lexical editor upgrade).

## Model extensions — `js/editor/model.js`

- `footnote`: `{ id, index, text: Block[] }` — body contains a `footnoteRef` marker run.
- `comment`: `{ id, author, date, text }` attached to a range. Represent as an
  annotation spanning runs: `{ type:'commentRange', id, start/end run refs }` plus a
  `comment` record in `doc.comments[]`.
- `trackedChange`: `{ author, date, kind: 'insert'|'delete'|'format' }` wrapping a run
  (`{ type:'insRun' }` / `{ type:'delRun' }`).
- Keep annotations as sibling data structures (`doc.footnotes`, `doc.comments`,
  `doc.revisions`) with inline markers, so normal block serialization is unchanged.

## Tasks

### 1. Import — `js/editor/ooxml.js`
- **Footnotes:** parse `word/footnotes.xml` (`w:footnote`, separator/continuation
  excluded); at each `w:footnoteReference` in the body, insert a `footnoteRef` marker;
  store footnote content blocks. Endnotes (`word/endnotes.xml`) via the same code path.
- **Comments:** parse `word/comments.xml`; track `w:commentRangeStart/End` in the body
  walker and attach a `commentRange` over the covered runs; pull author/date from the
  comment record.
- **Tracked changes:** `w:ins` → insert `insRun` runs with author/date; `w:del` →
  capture deleted text as `delRun` (stored, not rendered); `w:rPrChange` → store the
  prior formatting as `formatChange`.
- Any construct that fails to parse is downgraded to a warning (never a crash).

### 2. Export — `js/editor/docxExport.js`
- **Footnotes:** `docx` `FootnoteReferenceRun` + `footnotes` registered on the
  `Document`; write the same footnote text content.
- **Comments:** `docx` `CommentRangeStart`/`CommentRangeEnd` + `Comment`; set
  `comments` on the document; preserve author/date.
- **Tracked changes:** `docx` `InsertedTextRun`/`DeletedTextRun` with
  `revision: { author, date }`. Deleted runs are emitted as `w:del` so Word shows the
  strikethrough and history.
- **Round-trip invariant:** if an imported doc is exported without edits, the
  annotation parts must be byte-for-byte semantically identical (author, date, text,
  range positions). This is the primary test.

### 3. Viewing UI — `js/editor/annotations.js` (new)
- **Footnotes:** superscript marker in the text; clicking opens a small panel listing
  footnotes (`footnote index → text`), anchored like `linkTooltip.js`'s tooltip.
- **Comments:** comment markers (e.g. underline/accent + hover) and a right-side
  panel listing comments with author/date. Read-only; clicking a comment selects its
  range.
- **Tracked changes:** render insertions normally, deletions as strikethrough,
  format changes as-is; no accept/reject controls. A banner notes the document
  contains tracked changes.
- Keep all annotation UI in `js/editor/annotations.js`, lazily attached, so docs
  without annotations pay zero cost.

### 4. Pagination integration
- Annotation markers are inline runs — pagination's existing text/node splitting
  (`pagination.js`) handles them like any other run. Ensure `data-split` cloning
  preserves marker IDs (test: footnote in a paragraph that splits across pages).
- Header/footer chrome from M5 must not collide with annotation panels (separate
  z-index layers).

### 5. Fidelity matrix update
- Footnotes: import ✅, export ✅, round-trip ✅ (golden test).
- Comments: import ✅ (view), export ✅ (preserve), round-trip ✅ (preserve).
- Tracked changes: import ▶ (preserved), export ▶ (preserved), round-trip ▶.

## Acceptance criteria
- A Word doc with footnotes, comments, and tracked changes imports; footnotes and
  comments are viewable; changes show as insert/delete marks.
- Exporting that doc back opens in Word with all three constructs intact
  (authors/dates/text preserved).
- Export of a never-edited imported doc reproduces equivalent annotation XML.
- Nothing crashes on documents with malformed annotation parts — downgrade + warn.
